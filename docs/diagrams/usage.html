How to use it on the base story

Four loops, all on the cell, the 100 cities and the monitor. The sender side tunes the cell's playbook. The guard side tunes the monitor. A matrix runs scenarios side by side. An agent can run a matrix unattended and hand back a dataset.

SPEC §6.4, §9.6, §14.3, §14.8, §16, §16.1, §19.4, §20 · BUILDPLAN M7, M8. Commands are the spec's. Output is the spec's example where it has one; <placeholders> mark what it does not fix.

Before the first run

Every command is non-interactive, takes --json, writes progress to stderr, and exits 0, 1 (a bug), 2 (invalid config), 3 (budget), 4 (provider) or 5 (interrupted).

The sender side: tune the cell's playbook

The cell's understanding is P₁, shared by S and R. A new playbook is a new file and a new experiment one field away from the base story. Try it cheaply, read single stories, then run it for real and read its grid row.

sender side harness results then 
$ simmons new assoc-v4 --from assoc-v3
# writes experiments/assoc-v4.json with only the non-default fields; then point sender_prompt at v4
{
  "name": "assoc-v4",
  "description": "A cell that hides the city in place associations, against the reference monitor.",
  "sender_prompt": "prompts/sender/associations-v4.md"
}
$ simmons run experiments/assoc-v4.json --episodes 40 --scratch
# stderr, one line per wave (SPEC §20); with wave_size 1 a wave is one episode

# at the end, one line (SPEC §9.6): outcome counts, hit rate, catch rate, false-alarm rate, spend, run directory
$ simmons show runs-local/assoc-v4/<run-id> --episode 17

The guard side: tune the monitor

The monitor's brief is the template templates/au-meeting/guard.md plus P₂. A new P₂ runs against the reference cell. Read its curve, the genuine stories it blocked, and the stories it let through.

$ simmons run experiments/guard-v6-vs-ref.json
$ simmons view runs/guard-v6-vs-ref/<run-id> --open
# writes the run's view/ pages, prints the path, opens view/index.html

A matrix of scenarios, filled by the team

v1.1 Matrices ship in v1.1. Declare it, check the price, fill it from two clones, read it. The worked example is the monitoring gap (SPEC §6.5). More on the Matrices page.

person A person B money results data then 
$ simmons validate matrices/monitoring-gap.json
# the cells, the slots, the estimate and the budget line: 6 cells, 12 slots, budget_usd 100
$ simmons matrix run matrices/monitoring-gap.json --dry-run
# the ordered slots with each estimate, the running total, and the slot after which the budget runs out
$ simmons matrix run matrices/monitoring-gap.json --shard 1/2      # a teammate runs --shard 2/2
$ simmons matrix status matrices/monitoring-gap.json
# slot states, authors, extensions and forks, orphans, spend against budget_usd, estimate to finish, next slots
$ simmons pivot --matrix monitoring-gap --rows axis.pair --cols axis.guard --metric hit_rate,decode_gap
$ simmons compare monitoring-gap:sonnet__haiku monitoring-gap:sonnet__opus
# differs: only models.guard (haiku vs opus) · pairing per shared seed · each rate for A and B, and B − A with a Newcombe 95% interval
