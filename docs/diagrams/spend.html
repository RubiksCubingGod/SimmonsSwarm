Spend: the circuit breaker

A 200-episode run of the base story makes about 600 role calls (the cell or the correspondent writes, the monitor reads, R names a city), plus an exit interview of S after each of the cell's 140 stories. Every one of them reserves its worst case before it is sent. Code caps a run at $20 and a matrix at $100. OpenRouter's key limit and prepaid credit sit outside the code, as backstops.

SPEC §19, §12.9, §15.1, §15.4, §9.1, §9.5, §14.8 · BUILDPLAN T02e, T08 (v1.0); T09, T11, T20 (v1.1) · EVALUATION E-06, E-14, E-15, E-16, E-33. In v1.0: the breaker, the journal, real prices and the key-limit cap. budget --audit, resume and the matrix ceiling's enforcement arrive in v1.1.

One call attempt through the breaker

The runner calls spend.Breaker around every attempt: reserve before it leaves, then settle or unresolved when it returns. Preflight calls and retries go through it too.

harness step settled unresolved trips the breaker data control

open How a refused attempt's reservation is released (a 402, 429 or 5xx that carries no usage.cost) is not stated. Read literally, §12.9 keeps any reservation that never settles counted at its worst case.

The ledger against the cap

Settled spend, every open reservation and every unresolved charge all count. The next attempt is reserved only if it still fits.

settled open reservations unresolved next reservation the cap

The journal, spend.jsonl, as SPEC §12.9 shows it. Each line is flushed before the request is submitted, and again when it settles.

lifetime spend = Σ settle + Σ reservations never settled (open or unresolved)
Breaker.spent_usd() = settled + unresolved + open

The bound is loose on purpose. In the example, guard attempt e17-guard-1 reserved $0.0310 and settled at $0.0042. Unknown charges stay at their worst case until simmons budget --audit looks each one up on OpenRouter by generation id. Calls that belonged to unfinished episodes are journaled too, so no paid call disappears.

What trips it, and what happens next

A tripped breaker is not an error. The run stops cleanly, keeps every paid call on record, and can be resumed while room remains.

Nested ceilings

Five layers, from one call to the account. The inner three are our code. The outer two are OpenRouter's, and still hold if our code is wrong.

The estimate is not the guarantee

Two separate code paths on purpose. The estimate refuses a run before any call. The reservation bound enforces the cap, call by call.

open shadow_decode is now on by default, which adds one receiver call per CATCH. SPEC §19.2 does not say the estimate counts it. The reservation bound covers it either way, since every shadow call is an attempt like any other.

How we know the ceilings hold

Guardrail (EVALUATION.md): No run spends more than $20; no matrix more than $100. Neither ceiling can be raised without a code change.

Commands

Every command is non-interactive and takes --json. Exit 3 always means money: refused before starting, or the breaker tripped.

# kind counts and the estimate; writes nothing; exit 0 if it fits, 3 if not
$ simmons run experiments/reference.json --dry-run
# a cheap try, written under runs-local/
$ simmons run experiments/reference.json --episodes 40 --scratch
# key limit, usage (all-time, today, this week), remaining credit,
# spend by author and experiment, and how many runs the remainder buys
$ simmons budget
# every call's recorded cost against OpenRouter's, by generation id
$ simmons budget --audit runs/<experiment>/<run-id>
# spend totals by author, experiment and matrix
$ simmons ls --cost
# every missing slot with its estimate, the running total and the budget cut
$ simmons matrix run matrices/<m>.json --dry-run

decided 2026-10-03 All real model traffic goes through OpenRouter in v1: one key (OPENROUTER_API_KEY), one adapter, and the exact cost of every call in usage.cost. Fake models cost nothing unless params.price_in and params.price_out are set, which is how the tests trip the breaker.
