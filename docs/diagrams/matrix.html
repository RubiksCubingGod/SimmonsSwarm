Matrices: scenarios side by side

A matrix runs scenarios around the base story side by side. It is one file: a base experiment, axes and seeds. It expands into ordinary experiments, four people fill it from their own machines, and anyone reads it back as one dataset.

SPEC §6.5, §6.6, §14.4 to §14.8, §19.5 · BUILDPLAN M8 (v1.1), T18 to T21, T24 · EVALUATION E-30 to E-35

Scenarios around the base story

Each scenario is one or two fields away from experiments/reference.json. A matrix axis is exactly that: a field, or a patch of fields, with a label per value.

The base story A scenario a patch of one or two fields

One file, six cells, twelve slots

The worked example is the monitoring gap, Atin's first experiment after v1 (SPEC §6.5): hold the cell strong and step the monitor down, and step the cell up against a fixed monitor.

Coverage: what a slot can be

simmons matrix status expands the matrix, hashes every cell, scans the run directories and classifies every slot. Nothing about coverage is stored: it is computed from runs/ every time (assumption 24). Under the default log_scope: "experiment", a slot is one trajectory.

a complete run's episodes a run still going not there the cell's episodes

open SPEC §14.7's --json example still counts "duplicate": 1 in slots for this matrix, which runs under the default log_scope: "experiment", where the states are extended and fork. The example's spend line is {"usd": 23.10, "budget_usd": 100.0, "remaining_usd": 76.90}.

matrix run: four people, one matrix

The command keeps no state of its own. Each pass recomputes coverage, so it can be stopped and rerun at any time. With wave_size: 1 every run is sequential, so a matrix fills fastest with several shards side by side (SPEC §14.8).

The dataset and the frame

simmons dataset --matrix monitoring-gap flattens every run into one row. A pivot pools rows into cells by id.config, places cells into buckets, and checks the fields it was not asked to compare.

Pairing. plans: paired means every seed has one plan_hash across the selection: every bucket faced the same meeting cities in the same order. Prompts and models never move the plan (SPEC §8).
