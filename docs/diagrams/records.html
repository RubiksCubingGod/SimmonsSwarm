How a run is identified

Every id is a SHA-256 of canonical JSON, with each file replaced by the hash of its bytes (§6.3). Ids decide what pools and what compares.

Four people, one grid, no merge conflicts

Each run lands in a new directory named with its author, so a push only ever adds files. Nothing derived is committed, so there is nothing to merge.

a person's machine committed gitignored data

Content is append-only

Add new prompt, experiment and cover-task files. Never edit one a committed run used: make v<N+1>. simmons validate fails when a file differs from a committed run's snapshot.

Hands off others' runs

Never edit or delete another person's run directory or personal folder. Names are unique by path; a clash shows up as a loud git add/add conflict.

One person per slot

Two runs that inherit the same history are a fork. Pull before running a slot by hand; matrix run shards guarantee it for matrices. Both branches stay valid data.
